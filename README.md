# TCG Tracker

A price cache and collection tracker for Pokémon, Magic: The Gathering and Riftbound cards.

The app keeps a local catalog of sets and cards, caches prices from two free-tier APIs, and lets signed-in users track what they own and what it's worth. The hard constraint shaping everything is that both price APIs allow about **100 requests per day**, so the app fetches lazily, caches everything in Postgres, and counts every outbound request.

Live: https://tcg-tracker-gold-three.vercel.app

## How it works

- **Catalog** comes from [TCG API](https://tcgapi.dev) (sets, cards, images, market price per printing), imported once per game with `pnpm sync:catalog`.
- **Condition prices** (Near Mint → Damaged) come from [JustTCG](https://justtcg.com), fetched the first time someone views a card and cached for 24 hours.
- **Collections** reference a `card_variant` (printing × condition × language) and a Better Auth user.
- **Daily refresh** (`pnpm sync:prices`, run by GitHub Actions) updates prices only for cards that appear in someone's collection, stalest first.
- Every API call goes through a quota check in the `api_usage_daily` table, so the app can never exceed the daily budget.

## Stack

Next.js 16 (App Router, Cache Components) · TypeScript · [StyleX](https://stylexjs.com) · [Neon](https://neon.com) Postgres · [Drizzle ORM](https://orm.drizzle.team) · [Better Auth](https://www.better-auth.com) · pnpm · Vitest

## Getting started

### Prerequisites

- Node.js 22+ and pnpm 12 (the version is pinned in `package.json`; pnpm switches automatically)
- A [Neon](https://console.neon.tech) project
- API keys from [JustTCG](https://justtcg.com/dashboard) and [TCG API](https://tcgapi.dev/quickstart) (both have free tiers)

### Setup

1. Install dependencies:
   ```bash
   pnpm install
   ```

2. Create `.env.local` from the example and fill it in:
   ```bash
   cp .env.example .env.local
   ```
   | Variable | Where it comes from |
   |---|---|
   | `DATABASE_URL` | Neon **pooled** connection string (host contains `-pooler`) |
   | `DATABASE_URL_UNPOOLED` | Neon **direct** connection string (used for migrations) |
   | `JUSTTCG_API_KEY`, `TCGAPI_API_KEY` | The two API dashboards |
   | `BETTER_AUTH_SECRET` | `openssl rand -base64 32` |
   | `BETTER_AUTH_URL` | `http://localhost:3000` |

   If you use the Neon CLI, `neon link` followed by `neon checkout <your-name> --create` creates a branch for you (an instant copy of production) and writes its database URLs into `.env.local`.

3. Create the schema:
   ```bash
   pnpm db:migrate
   ```

4. Seed the three games and import a catalog. Riftbound is the smallest (about 30 requests):
   ```bash
   pnpm db:seed
   ```
   ```bash
   pnpm sync:catalog riftbound
   ```
   The import stops at its request budget (default 40) and resumes where it left off on the next run.

5. Start the dev server:
   ```bash
   pnpm dev
   ```
   Open http://localhost:3000, pick a set, open a card. The first view of a card fetches its condition prices from JustTCG; later views read from the database.

### Scripts

| Script | What it does |
|---|---|
| `pnpm dev` / `pnpm build` / `pnpm start` | Next.js |
| `pnpm lint` / `pnpm test` | ESLint (incl. StyleX rules) / Vitest |
| `pnpm db:generate` | Generate a migration after editing `src/db/schema.ts` |
| `pnpm db:migrate` | Apply migrations (uses the direct URL) |
| `pnpm db:seed` | Upsert the `game` rows |
| `pnpm db:studio` | Drizzle Studio |
| `pnpm sync:catalog <game> [--max-requests N]` | Import or refresh a game's sets and cards from TCG API |
| `pnpm sync:prices [--max-requests N] [--source justtcg\|tcgapi]` | Refresh prices for cards in collections |
| `pnpm auth:generate` | Regenerate `src/db/auth-schema.ts` after changing `src/lib/auth.ts` |

Game ids are `pokemon`, `mtg` and `riftbound`.

```
    normalize/    Condition names → NM|LP|MP|HP|DMG, dollars → cents

    queries/      Read helpers for pages
    actions/      Server actions (collection mutations)
drizzle/          SQL migrations
scripts/          CLI entry points for the sync jobs
.github/workflows Daily price sync
```

## Working with the database

- **Migrations** are generated by Drizzle from `src/db/schema.ts`. Never edit the database by hand.
- **Better Auth's tables** are generated by its CLI (`pnpm auth:generate`), then migrated like everything else.
- **Branches:** `production` is the deployed database. Develop on your own Neon branch (`neon checkout <name> --create`), which is an instant copy of production. Test migrations there first.
- Money is stored as integer cents. External ids are stored as text.

## Deployment

The app deploys to Vercel from `main`; pull requests get preview deployments that use the Neon `dev` branch. GitHub Actions runs `pnpm sync:prices` daily at 06:00 UTC, then continues any in-progress catalog imports, and needs `DATABASE_URL`, `JUSTTCG_API_KEY` and `TCGAPI_API_KEY` as repository secrets. See `AGENTS.md` for the full operational notes, API quirks and conventions.

## Notes

- Both APIs' free tiers are for non-commercial use.
- JustTCG doesn't index unreleased sets; those cards show "No condition prices yet" until it does.
- TCG API's free tier exposes 7 days of price history and no sales volume; the app builds its own history from daily snapshots.
